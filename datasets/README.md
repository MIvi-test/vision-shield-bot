# Наборы изображений

Размеченные изображения для проверки и оценки CV-моделей (S1-15). Правила разметки — [docs/dataset.md](../docs/dataset.md), политика модерации — [docs/policy.md](../docs/policy.md). Сбор и версии набора ведёт Dev4, критерии разметки и перепроверку — Dev3.

В Git лежат только манифесты, схема и скрипты. Сами изображения скачиваются по манифесту в `data/datasets/`, которая исключена из Git.

## Быстрый старт

```bash
uv sync --locked
uv run python datasets/tools/fetch_dataset.py datasets/nature/manifest.jsonl
```

Изображения появятся в `data/datasets/nature/` с именами по `id`: `nat-0001.jpg`, `nat-0002.jpg` и т. д. Повторный запуск ничего не качает заново, только сверяет хеши. Первая загрузка — около 400 МБ.

Скрипт сверяет SHA-256 каждого файла с манифестом. Файл с другим хешем удаляется, в выводе появляется `MISMATCH <id>`, код возврата — 1.

## Состав

| Набор | Тема | Строк | `suitable` | `off_topic` | `borderline` | Авторов |
| --- | --- | --- | --- | --- | --- | --- |
| [`nature/`](nature/manifest.jsonl) | «Природа» (`nature-v0`) | 77 | 21 | 43 | 13 (из них `nsfw` — 1, `spam` — 1) | 48 |

Это первый срез для проверки моделей на CPU (S1-09). Класса `prohibited` в нём нет. Все строки — `split: "tuning"`, см. «Разделение данных».

## Структура

```text
datasets/
  manifest.schema.json    # JSON Schema строки манифеста
  nature/manifest.jsonl   # одна строка — одно изображение
  tools/
    commons.py            # общий код: API Commons, фильтры, безопасная загрузка
    find_candidates.py    # поиск и скачивание кандидатов
    build_manifest.py     # шаблон разметки и сборка манифеста
    fetch_dataset.py      # загрузка набора по манифесту
data/                     # вне Git
  candidates/<набор>/     # кандидаты, candidates.jsonl, labels.txt
  datasets/<набор>/       # скачанный набор
```

Проверки: `tests/test_dataset_manifest.py` (схема и правила манифеста), `tests/test_dataset_commons.py`, `tests/test_dataset_fetch.py`, `tests/test_dataset_build.py`. Все работают без сети и запускаются в CI вместе с остальными тестами.

## Строка манифеста

```json
{"id": "nat-0001", "sha256": "…", "label": "suitable", "category": null, "split": "tuning", "source_url": "https://commons.wikimedia.org/wiki/File:…", "file_url": "https://upload.wikimedia.org/wikipedia/commons/…", "license": "CC-BY-SA-3.0", "author": "…", "model_release": null, "labeled_by": "dev4", "reviewed_by": null, "notes": ""}
```

Поля описаны в `docs/dataset.md` §5. Сверх него добавлено одно поле:

- `file_url` — прямая ссылка на оригинал файла без параметров запроса. По ней качает скрипт. `source_url` — страница файла на Commons с автором и лицензией, она для человека.

Схема дополнительно требует: `sha256` — 64 строчных шестнадцатеричных символа; `license` — идентификатор SPDX из разрешённых; `author` — текст без HTML; `model_release` — только `true` или `null`; `reviewed_by` заполнен у `borderline` и `prohibited`; категория есть только у `borderline` и `prohibited`. Тест также проверяет, что `id` и `sha256` не повторяются, `id` идут подряд и один автор не попадает одновременно в `tuning` и `control`.

## Как добавить изображения

1. **Найти кандидатов.** Категории — с сайта Wikimedia Commons, без префикса `Category:`.
   ```bash
   uv run python datasets/tools/find_candidates.py --category "Quality images of lakes" --limit 5
   ```
   Скрипт скачивает подходящие файлы в `data/candidates/nature/` и записывает их данные в `candidates.jsonl`. В конце печатает, сколько файлов отброшено и почему.
2. **Создать шаблон разметки.**
   ```bash
   uv run python datasets/tools/build_manifest.py template
   ```
   В `data/candidates/nature/labels.txt` добавятся новые файлы с меткой `?`.
3. **Разметить.** Человек смотрит каждое изображение и заменяет `?` на `suitable`, `off_topic`, `borderline`, `borderline:<категория>` или `skip`. После второй `|` пишется заметка, для `borderline` и `skip` она обязательна. Скрипты метку не ставят.
4. **Собрать манифест.**
   ```bash
   uv run python datasets/tools/build_manifest.py build
   ```
   Новые строки дописываются в конец, номера продолжаются. Если где-то осталась метка `?`, манифест не меняется. Если у одного автора больше 5 снимков, скрипт предупредит.
5. **Проверить** командами из `CONTRIBUTING.md` и открыть PR. Dev3 перепроверяет все `borderline` и `prohibited`, а также случайные 20 % остальных, и вписывает себя в `reviewed_by`. До этого тест манифеста красный.

Номера `id` назначаются при сборке. Уже опубликованные строки не перенумеровываются и не удаляются: исправление метки — новая версия строки в PR с объяснением.

## Что отбрасывает поиск

Лимиты берутся из [media-профиля](../packages/contracts/policies/media-profile-v0.json), поэтому изображения набора проходят и через настоящий конвейер.

| Правило | Причина в выводе |
| --- | --- |
| Формат не JPEG, PNG или WEBP | `format …` |
| Больше 10 МиБ | `file too large` |
| Больше 25 млн пикселей или сторона больше 8000 | `too many pixels` |
| Короткая сторона меньше 512 | `too small` |
| Commons отметил узнаваемых людей (`personality`) | `identifiable people` |
| Лицензия не из списка ниже | `license …` |
| Не указан автор | `no author` |
| Ссылка ведёт не на Wikimedia | `bad url` |
| Файл уже в манифесте или среди кандидатов | `already known` |
| Больше `--max-per-author` снимков автора за запуск (по умолчанию 2) | `author limit` |

Отметка `personality` есть не у всех снимков с людьми. Узнаваемое лицо, замеченное при разметке, получает `skip`: model release у нас нет (`docs/dataset.md` §4).

## Источник и лицензии

Все изображения — с [Wikimedia Commons](https://commons.wikimedia.org/). Допустимы `CC0-1.0`, `PDM-1.0` (общественное достояние), `CC-BY-*` и `CC-BY-SA-*` версий 1.0–4.0. Изображения не распространяются вместе с проектом: в репозитории только ссылки.

Лицензии CC BY и CC BY-SA требуют указывать автора и лицензию при любом показе изображения. Если снимок из набора попадёт на слайд, в отчёт или в демо-канал, рядом нужны автор, лицензия и ссылка на `source_url`. Для CC BY-SA производная работа (например, коллаж) распространяется под той же лицензией.

Скрипты обращаются к API с User-Agent проекта и паузой между запросами, по одному запросу за раз, как требуют правила Wikimedia для автоматических клиентов.

## Разделение данных

- **Первый срез целиком — `tuning`.** В S1-09 модели прогоняются на всех его изображениях, поэтому ни одно из них не годится для контрольной оценки.
- **`control` собирается в S2-09** из изображений, которые модель ещё не видела.
- Делим по автору: все снимки одного автора — в одной части. Примерно 70 % `tuning`, 30 % `control`, в `control` — все метки.
- Контрольная часть замораживается версией `dataset-nature-v1` до подбора порогов (S3-02). После оценки она не меняется: ошибки модели идут в следующую версию набора (`docs/dataset.md` §6).

## Безопасность

- **Хеш гарантирует целостность, а не безопасность.** Сверка SHA-256 доказывает, что файл тот же, что был размечен, и защищает от подмены по ссылке. Изначально вредоносный файл она не обнаружит.
- **Скрипты не декодируют изображения.** Они только скачивают байты, проверяют размер и хеш. Загрузка разрешена только с `upload.wikimedia.org`, обрывается после 10 МиБ, файл сначала пишется во временный `.part`.
- **Файлы — неочищенные оригиналы** с EXIF и другими метаданными. Очистку выполняет media worker (S2-04). Оценку качества CV в спринте 3 проводить на очищенных копиях, как в рабочем конвейере: CV читает только `sanitized/` (`docs/security.md` §1).
- **Класс `prohibited`** хранится отдельно от этого набора, не в Git и не в общих облачных папках, доступ только у Dev3 и Dev4 (`docs/dataset.md` §4).
