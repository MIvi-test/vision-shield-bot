# Примеры ответов MAX для адаптера и эмулятора

В [fixtures/](fixtures/) — 22 обезличенных примера реальных ответов MAX,
полученных 24 октября 2026 через `maxapi 1.2.3`.
Выводы о возможностях и правах — в [протоколе S1-04](../../../docs/results/max-check.md).

## Кому и зачем нужны JSON

- **Dev1:** воспроизвести используемые `maxapi` HTTP-контракты в эмуляторе
  S1-05 и S2-12. Библиотека обращается к серверу; при mock-режиме этим сервером
  становится эмулятор, поэтому формы ответов остаются важны.
- **Dev2:** сверить входящие события и ответы SDK с реальным API при разработке
  MAX-адаптера. Решения о заявках и содержании ответов принадлежат Backend.
- **S5-02:** использовать сохранённые ответы как данные контрактных тестов
  эмулятора, без обращения к реальному MAX на каждом запуске CI.

Файлы не загружаются в MAX и не являются конфигурацией приложения.
Готовые тесты и код SDK в этом каталоге не поставляются.

## Состав

| Группа | Примеры |
| --- | --- |
| Служебные ответы | `get-me.json`, `get-channel.json`, `get-channel-membership.json` |
| Polling | `updates-text.json`, `updates-image.json`, `updates-file.json`, `updates-forward.json`, `updates-channel-post.json`, `updates-text-and-image.json`, `updates-empty.json` |
| Отправка в диалог | `post-message-text.json`, `post-message-image.json` |
| Загрузка и публикация | `post-uploads-image.json`, `upload-image-response.json`, `post-channel-image-keyboard.json` |
| Чтение и статистика | `get-channel-messages.json`, `get-message-by-id.json`, `get-message-statistics.json` |
| Callback | `updates-callback.json`, `post-callback-answer.json` |
| Удаление | `delete-message.json`, `get-deleted-message.json` |

Каждый JSON содержит `provenance`, `request` (метод, шаблон пути, query),
HTTP `status` и `body` ответа. В `delete-message.json` перечислены два сценария:
первичное и повторное удаление дали одинаковый ответ. В статистике сохранён
один пример: после установки, замены и снятия реакции данные реакций
не появились. `upload-image-response.json` — ответ upload-сервера,
а не отдельный метод Bot API.

## Обезличивание и границы использования

Имена, ID, тексты, timestamps, payload, токены и URL заменены синтетическими
значениями. URL ведут на `example.invalid`; числовые типы, вложенность,
пустые и отсутствующие поля сохранены. Связи ID между опубликованным постом,
callback, чтением и удалением сохранены. Размеры файлов и счётчики оставлены.
Ответы получены от реального API; это не примеры, придуманные по документации.

Примеры описывают наблюдавшиеся случаи и не являются полной схемой API.
Новые ответы перед добавлением вручную обезличиваются и проверяются на секреты;
сырые ответы, рабочие ссылки и бинарные файлы в Git не добавляются.
Dev2 подтверждает применимость форматов к адаптеру при ревью.
