# Политика модерации v0

Часть архитектурной документации; обзор — в [ARCHITECTURE.md](ARCHITECTURE.md). Задача S1-10, владелец Dev3, проверка Dev4. Машиночитаемые файлы — в [`packages/contracts/policies/`](../packages/contracts/policies/README.md), их согласованность проверяет `tests/test_moderation_policy.py`.

**Статус:** черновик v0. Тема, запреты и критерии качества — предложение Dev3 до подтверждения в S1-14. Пороги модели здесь не задаются: их выбирает S3-02 на данных настройки.

## 1. Из чего состоит политика

| Файл | Что задаёт | Кто меняет |
| --- | --- | --- |
| `campaigns/<slug>-vN.json` | Тема, примеры для автора, шаблоны CV, запрещённые категории, режим `manual`/`auto`, пороги, правило дублей | Тему — маркетинг; шаблоны, запреты, пороги и режим проверяет Dev3 |
| `media-profile-v0.json` | Входные форматы, лимиты файла/пикселей/кадров/декодирования, параметры очистки | Только Dev3 с ревью Dev4: это граница защиты, а не настройка кампании |
| `reason-codes.json` | Внутренние коды причин, их эффект и нейтральный текст для автора | Dev3; тексты согласует Dev2 (бот) |

**Тема настраиваемая.** Продуктовое решение: в эксплуатации тему фото задаёт маркетинг. В v0 это файл кампании, изменённый через PR, и тест схемы. Позже — форма в панели `admin`, которая создаёт тот же документ. Код workers тему не знает: CV получает снимок политики в задании ([events](../packages/contracts/events/README.md)).

**Правила версий:**

- Версия со статусом `approved` неизменна. Любая правка темы, шаблонов или порогов — новая `policy_version` (`nature-v1`, `nature-v2`). Заявка и результат CV хранят версию, по которой они проверены.
- Согласие пользователя (S1-06) привязано к `rules_version` текста правил. Если смена политики меняет то, на что соглашается автор (тема, запреты), Dev2 выпускает новую версию текста правил и запрашивает согласие заново.
- **Новая тема стартует в `manual`.** Качество CV зависит от темы, поэтому пороги одной темы не переносятся на другую. Режим `auto` разрешён схемой только при `calibrated: true` и ссылке на отчёт оценки для этой версии. Без оценки работает ручная модерация. Это ограничение для маркетинга: новая тема сразу принимается, но автоматически решается только после замера.

Демо-кампания v0 — «Природа» (`nature-v0`). Она нужна для датасета (S1-15), замеров (S1-09) и демо и не означает, что тема продукта выбрана навсегда.

## 2. Форматы и технические лимиты (media-v0)

Формат определяет media worker по сигнатуре содержимого. MIME и расширение от MAX не учитываются: S1-04 показала, что MAX отдаёт фото как WEBP, файл PNG приходит как `application/octet-stream`, а опубликованный PNG скачивается как JPEG.

| Параметр | v0 | Почему так |
| --- | --- | --- |
| Входные форматы | JPEG (`FF D8 FF`), PNG (`89 50 4E 47 0D 0A 1A 0A`), WEBP (`RIFF....WEBP`) | **WEBP принимаем**: это основной формат фото из MAX, отказ отклонял бы почти все заявки. HEIC, GIF, TIFF, BMP, SVG не принимаются: лишние декодеры расширяют поверхность атаки, а в фото из MAX они не встречались |
| Размер файла | ≤ 10 МиБ (10 485 760 байт) | Фото, отправленное как фото, MAX пережимает в WEBP, и оно весит заметно меньше. JPEG с телефона, отправленный файлом, обычно укладывается в 10 МиБ. Предел MAX для загрузки (50 МБ) нам не нужен. Fetcher (Dev2) обрывает скачивание по тому же значению, media проверяет повторно |
| Пиксели | ≤ 25 000 000, сторона ≤ 8000 px | Защита от decompression bomb: проверяется по заголовку до полного декодирования. Выход всё равно ≤ 2048 px, поэтому больший вход качества не добавляет. Снимок 48 Мп, отправленный файлом, отклоняется как `IMAGE_TOO_LARGE` |
| Минимум | меньшая сторона ≥ 512 px | Меньше — непригодно для ленты |
| Кадры | ровно 1 | Анимированные WEBP и APNG (`ANIM`/`acTL`) отклоняются как `ANIMATED_IMAGE` |
| Декодирование | отдельный процесс, ≤ 5 с и ≤ 512 МиБ памяти; вся задача ≤ 30 с | 25 Мп RGB — около 75 МБ на копию, при поворотах и конвертации нужно 3–4 копии, то есть ~300 МБ. Значения предварительные, уточняются замером в S2-04 |
| Выход | JPEG q=85, длинная сторона ≤ 2048 px, RGB, sRGB | Единый формат для превью, CV и публикации. q=85 визуально не отличается от 90, а файл примерно на треть меньше; MAX всё равно пережимает фото при публикации. Предел MAX (7680×7680) соблюдается с запасом |
| Очистка | Ориентация из EXIF применяется, затем удаляются EXIF/XMP/ICC и прочие метаданные; ICC → sRGB; прозрачность сводится на белый фон | Метаданные могут содержать геопозицию и модель устройства. В `sanitized/` попадает только перекодированный файл, копия оригинала очисткой не считается |

Любой выход за лимит — технический отказ с кодом из §5. Его не может одобрить модератор: нужна новая загрузка.

## 3. Запрещённый контент

Запреты действуют в любой кампании, независимо от темы.

| Категория | Как проверяется в v0 | Действие |
| --- | --- | --- |
| Сексуальный контент, обнажённость | Отдельный NSFW-классификатор (кандидаты — S1-09) | Высокий score → `NSFW_DETECTED` (отклонение), средний → `NSFW_SUSPECTED` (человеку) |
| Насилие, кровь, травмы, мёртвые животные, оружие | Шаблоны CLIP `violence` | Только `PROHIBITED_SUSPECTED` → человеку. Zero-shot шаблоны недостаточно точны для автоотказа |
| Персональные данные: документы, номера машин, экраны с личной информацией | Шаблоны CLIP `personal_data` | → человеку |
| Реклама и спам: баннеры, QR-коды, логотипы, много текста | Шаблоны CLIP `spam` | → человеку |
| Ребёнок — главный объект кадра | Шаблоны CLIP `minors` | → человеку. Публикация в публичном канале требует согласия законного представителя, которого бот не собирает, поэтому модератор такие фото отклоняет |
| Символика экстремизма и ненависти | **Не покрыто автоматически** | Только модератор. Явное ограничение v0 |
| Чужое фото, генерация ИИ, нарушение авторских прав | **Не проверяется** | Автор подтверждает права в согласии; модератор отклоняет очевидные случаи (водяной знак, известный снимок) |

## 4. Порядок принятия решения

1. **Fetcher** (Dev2): недоступное вложение — `ATTACHMENT_UNAVAILABLE`; больше лимита — `FILE_TOO_LARGE`. Дубль по SHA-256 в кампании — `DUPLICATE` (Backend, до декодирования).
2. **Media** (Dev3): сигнатура → лимиты по заголовку → декодирование в ограниченном процессе → очистка. Любая ошибка — `media.rejected` с техническим кодом, заявка `rejected`.
3. **Режим `manual`:** после успешной очистки заявка `review_required` без CV (спринт 2).
4. **Режим `auto`** (спринт 3), в CV проверки идут строго по порядку:
   1. NSFW ≥ `nsfw_reject_min` → `rejected` / `NSFW_DETECTED`.
   2. NSFW ≥ `nsfw_review_min` → `review_required` / `NSFW_SUSPECTED`.
   3. Любая запрещённая категория ≥ `prohibited_review_min` → `review_required` / `PROHIBITED_SUSPECTED`.
   4. Тема ≥ `topic_approve_min` → `approved` / `TOPIC_MATCH`.
   5. Тема ≤ `topic_reject_max` → `rejected` / `OFF_TOPIC`.
   6. Иначе → `review_required` / `LOW_TOPIC_CONFIDENCE`.
5. Ошибка CV, незагруженная модель, повторы исчерпаны → Backend ставит `review_required` / `CV_ERROR`. Ошибка никогда не даёт автоодобрения.

**Как считается score.** Для темы: косинусная близость изображения с каждым шаблоном, softmax по всем позитивным и негативным шаблонам темы, score темы — сумма вероятностей позитивных шаблонов. Для запрещённой категории: та же процедура по шаблонам категории против нейтральных шаблонов темы. NSFW: вероятность класса `nsfw` классификатора. Score — относительная мера сходства, а не вероятность правильного решения, и сравнивается только с порогами, выбранными для этой версии модели и политики.

## 5. Коды причин и тексты для автора

Источник истины — [`reason-codes.json`](../packages/contracts/policies/reason-codes.json). Автор видит только нейтральный текст; модели, пороги и внутренние коды не раскрываются.

| Код | Кто ставит | Итог | Модератор может одобрить |
| --- | --- | --- | --- |
| `ATTACHMENT_UNAVAILABLE` | fetcher | rejected | нет |
| `FILE_TOO_LARGE` | fetcher / media | rejected | нет |
| `DUPLICATE` | backend | rejected | нет |
| `UNSUPPORTED_FORMAT` | media | rejected | нет |
| `CORRUPTED_IMAGE` | media | rejected | нет |
| `IMAGE_TOO_LARGE` | media | rejected | нет |
| `IMAGE_TOO_SMALL` | media | rejected | нет |
| `ANIMATED_IMAGE` | media | rejected | нет |
| `DECODE_LIMIT_EXCEEDED` | media | rejected | нет |
| `TOPIC_MATCH` | cv | approved | — |
| `OFF_TOPIC` | cv | rejected | да, при пересмотре |
| `LOW_TOPIC_CONFIDENCE` | cv | review_required | да |
| `NSFW_DETECTED` | cv | rejected | да, если это ложное срабатывание |
| `NSFW_SUSPECTED` | cv | review_required | да |
| `PROHIBITED_SUSPECTED` | cv | review_required | да |
| `CV_ERROR` | backend | review_required | да |
| `MODERATOR_APPROVED` | moderator | approved | — |
| `MODERATOR_REJECTED_OFF_TOPIC` | moderator | rejected | да, при пересмотре |
| `MODERATOR_REJECTED_PROHIBITED` | moderator | rejected | да, при пересмотре |
| `MODERATOR_REJECTED_LOW_QUALITY` | moderator | rejected | да, при пересмотре |
| `MODERATOR_REJECTED_OTHER` | moderator | rejected | да, при пересмотре |

`FILE_TOO_LARGE` в JSON отмечен stage `fetcher`, но тот же код возвращает media при повторной проверке. Отправка `review_required` автору сообщает только «на проверке»; итоговое уведомление уходит после решения.

## 6. Правила ручной проверки

Модератор видит только очищенное превью, причины, score и историю ([S2-06/S2-07](sprints.md)).

- **Технический отказ не одобряется.** Кнопка одобрения недоступна, API возвращает ошибку. Автор должен прислать файл заново.
- **Каждое решение — с кодом из §5** (`MODERATOR_*`). `MODERATOR_REJECTED_OTHER` требует внутреннего комментария, который автор не видит.
- **Запреты из §3 важнее темы.** Подходящее по теме фото с ребёнком в главной роли, документом или номером машины отклоняется как `MODERATOR_REJECTED_PROHIBITED`.
- **Тема:** одобрять, если природа — главный объект кадра; при сомнении смотреть примеры темы в файле кампании и правила пограничных случаев в [dataset.md](dataset.md#3-пограничные-случаи).
- **Качество:** отклонять сильное размытие, полную засветку или темноту, коллажи, скриншоты, фото экрана. Художественная обработка допустима.
- **Ложные срабатывания CV** модератор исправляет одобрением; заявка попадает в набор ошибок для S4-06 (без копирования фото в репозиторий).
- Конфликт версии (`409`) — обновить карточку и решить заново, не повторять запрос вслепую.

## 7. Критерии приёмки качества (для S3-02)

Предложение Dev3, утверждается командой до первой оценки. Изменение критериев после измерения требует явного решения команды ([moderation.md](moderation.md)).

**Классы оценки:** `suitable`, `off_topic`, `borderline`, `prohibited` (по [dataset.md](dataset.md)). Технически невалидные файлы проверяются тестами media, а не метриками CV.

**Минимальный контрольный набор** на тему кампании: ≥ 100 `suitable`, ≥ 100 `off_topic`, ≥ 30 `borderline`, ≥ 30 `prohibited`. Данные настройки — отдельный набор сопоставимого размера.

| Метрика на контрольном наборе | Критерий для включения `auto` |
| --- | --- |
| `prohibited`, одобренные автоматически | **0** — блокирующий критерий |
| Precision автоодобрения (доля `suitable` среди `approved`) | ≥ 0,95 |
| `suitable`, отклонённые автоматически | ≤ 5 % от `suitable` |
| Recall `prohibited` в `rejected ∪ review_required` | ≥ 0,95 |
| Доля `review_required` по всему набору | ≤ 40 % |
| Время CV на изображение на CPU стенда | p95 ≤ 3 с |
| Пиковая RAM CV worker | ≤ 2 ГиБ |

`borderline` не входит в precision/recall как правильный или неправильный ответ: для него считается только распределение по решениям, ожидаемо — в основном `review_required`. Отчёт содержит матрицу ошибок по классам, а не одну агрегированную цифру. Если критерии не выполнены, кампания остаётся в `manual`, MVP не объявляется готовым.

## 8. Открытые вопросы к S1-14

- Подтвердить, что тема задаётся кампанией, и формат изменения на время учебного проекта (PR с файлом).
- Подтвердить список запретов §3, особенно правило про детей в кадре и непокрытые категории.
- Кто утверждает новую версию политики со стороны продукта (маркетинг/организатор).
- **Маркетинг и автомодерация.** Тему маркетинг меняет сам, но для режима `auto` на новой теме нужны размеченный набор и подбор порогов (§7) — это работа Dev3, а не маркетинга. Варианты: новая тема всегда работает в `manual`; или добавить режим «подсказки», где CV показывает модератору оценку, но не решает сам (требует изменений Backend и панели). Нужно решение наставника.
- Подтвердить критерии §7 и что новая тема без оценки работает в `manual`.
