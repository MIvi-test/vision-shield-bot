# Риски и открытые решения

Часть архитектурной документации; обзор и карта документов — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Риски

| Риск | Признак | Мера | Владелец |
| --- | --- | --- | --- |
| Источник рейтинга через нативные реакции MAX не подтверждён | В S1-04 после установки, замены и снятия реакции API не вернул реакций; публикация, скачивание, чтение и удаление проверены | Callback-кнопки проверены; согласовать собственное голосование с наставником, не утверждать отсутствие другого API реакций; [протокол](results/max-check.md) | Dev1, Dev2, Dev4 |
| WEBP от MAX не входит в текущий план media JPEG/PNG | В S1-04 фото реально скачано как WEBP; файл PNG имел общий MIME | Согласовать поддержку WEBP или явное отклонение; определять формат по содержимому, учитывать перекодирование MAX | Dev2, Dev4 |
| Наставник не примет эмулятор для рейтинга | К спринту 5 нет согласования | Согласовать в спринте 1; подготовить кнопки голосования | Dev4, команда |

| Модель не помещается в CPU/RAM стенда | Замер в спринте 1 превышает ресурсы | Более лёгкие веса, одно задание на процесс, лимиты ресурсов | Dev3, Dev1 |
| Перегрузка Dev2, единственная точка отказа команды | Задачи критического пути копятся | Контракты заранее; разработка эмулятора у Dev1; розыгрыш в спринте 5; Dev1 и Dev4 умеют поднять backend | Dev2, команда |
| Сквозной сценарий не готов к сроку | Спринты 2–3 затягиваются | Опциональные функции только после e2e; вертикальные срезы вместо слоёв | Команда |
| Ошибки идемпотентности: дубли постов, потерянные события | Падают обязательные проверки | Outbox и inbox с первого сценария; fault injection | Dev2, Dev1 |
| Уязвимость декодера изображений | Публичная CVE в Pillow или зависимостях | Изоляция media, лимиты, сканирование зависимостей, своевременное обновление | Dev2, Dev4, Dev1 |

| Нет размеченного набора к настройке порогов | К спринту 3 набора нет | Собрать контрольный набор в спринте 2 из открытых и синтетических данных по критериям разметки | Dev4, Dev3 |
| Лицензии весов модели или тестовых изображений не разрешают использование | Лицензия не найдена или запрещает такое использование | Проверять при выборе, записывать источник | Dev3 — веса, Dev4 — изображения |
| Персональные данные реальных людей на демо | Реальные фото без согласия | Тестовые аккаунты и данные, правила [security.md](security.md) §3 | Dev4 |

## Открытые решения

До финальной интеграции команда закрывает:

- точные категории запретов и тему; веса моделей и пороги;
- сроки хранения и правило отзыва согласия ([security.md](security.md) §3);
- нужно ли формально учитывать 152-ФЗ, или для учебного демо достаточно минимизации — уточнить у наставника;
- поддержку WEBP и остальных форматов: S1-04 подтвердил WEBP, PNG как файл и перекодирование PNG в JPEG; media пока рассчитан на JPEG/PNG ([security.md](security.md) §1);
- источник рейтинга и допустимость собственных голосов — единственный пункт, где допустимость эмулятора не следует из постановки;
- правила участия нескольких фото одного автора и ничьих;
- политику повторной отправки того же файла, если умолчание из [data-model.md](data-model.md) §4 не подходит;
- гарантированный TTL ссылок: в S1-04 фото/файл скачаны без токена, одна ссылка доступна спустя 3 ч 47 мин 7 с; это не гарантия срока жизни;
- ресурсы демо-стенда;
- процедуру ручной сверки `publication_unknown`;
- критерии приёмки реального MAX.

S1-04 снял вопросы о полях callback и повторном удалении для тестового сценария:
см. [результаты](results/max-check.md). Эти наблюдения не задают гарантий
для всех прав, каналов и версий API.
