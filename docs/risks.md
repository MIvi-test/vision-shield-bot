Часть архитектурной документации; обзор и карта документов — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Риски

| Риск | Признак | Мера | Владелец |
| --- | --- | --- | --- |
| Источник рейтинга через нативные реакции MAX не подтверждён | В S1-04 после установки, замены и снятия реакции API не вернул реакций; публикация, скачивание, чтение и удаление проверены | Callback-кнопки проверены; согласовать собственное голосование с наставником, не утверждать отсутствие другого API реакций; [протокол](results/max-check.md) | Dev1, Dev2, Dev4 |
| WEBP от MAX не входит в исходное предложение media JPEG/PNG | В S1-04 фото реально скачано как WEBP; файл PNG имел общий MIME | Решено в S1-10: WEBP принимается по сигнатуре и перекодируется в JPEG, анимированный WEBP отклоняется ([policy.md](policy.md) §2) | Dev3, Dev4; приём согласует Dev2 |
| Наставник не примет эмулятор для рейтинга | К спринту 5 нет согласования | Согласовать в спринте 1; подготовить кнопки голосования | Dev4, команда |
| Качества CV не хватает, особенно для русских тем | Низкий precision/recall, большая доля ручной проверки | Размеченный набор заранее; пограничные заявки — в `review_required`; мультиязычная модель или англоязычные шаблоны | Dev3 |
| Модель не помещается в CPU/RAM стенда | Замер в спринте 1 превышает ресурсы | Более лёгкие веса, одно задание на процесс, лимиты ресурсов | Dev3, Dev1 |
| Перегрузка Dev2, единственная точка отказа команды | Задачи жизненного цикла копятся | Эмулятор у Dev1, media/CV у Dev3; контракты согласуются заранее; сначала ручной путь, затем CV; Dev1 и Dev4 умеют поднять Backend/consumer | Dev2, команда |
| Перегрузка Dev3 после передачи media | Безопасная обработка и исследование моделей конкурируют за время | Данные готовит Dev4 с первого спринта; изоляцию настраивает Dev1; готовые модели, ограниченный набор форматов, отдельный ручной результат до CV; оценить объём до обещания сроков | Dev3, команда |
| Сквозной сценарий не готов к сроку | Спринты 2–3 затягиваются | Опциональные функции только после e2e; вертикальные срезы вместо слоёв | Команда |
| Ошибки идемпотентности: дубли постов, потерянные события | Падают обязательные проверки | Outbox и inbox с первого сценария; fault injection | Dev2, Dev1 |
| Уязвимость декодера изображений | Публичная CVE в Pillow или зависимостях | Изоляция и лимиты с момента появления media, сканирование зависимостей, своевременное обновление | Dev3, Dev4, Dev1 |
| Утечка токена бота | Сработал поиск секретов; токен в логах или истории git | Секреты вне git, сканирование в CI, процедура ротации | Dev1 |
| Нет данных или контрольный набор использован для настройки | Исследование ждёт примеров; пороги выбраны по контрольным данным | Первые данные в S1-15, разделённые наборы в S2-09; критерии качества согласованы до оценки; при провале автопубликация выключена, MVP не принимается | Dev4, Dev3 |
| Сроки плана не соответствуют доступному времени | Большой этап объявлен двухнедельным без оценки | Оценивать остаток с учётом выполненной работы и зависимостей; делить этап на дополнительные спринты с запускаемым результатом | Команда |
| Учебный стенд ошибочно объявлен production | Нет проверенного восстановления, нагрузки или ответственного | После MVP завершить обязательные функции и подтвердить условия ограниченной эксплуатации; явно записать ограничения выпуска | Dev1, команда |
| Лицензии весов модели или тестовых изображений не разрешают использование | Лицензия не найдена или запрещает такое использование | Проверять при выборе, записывать источник | Dev3 — веса, Dev4 — изображения |
| Персональные данные реальных людей на демо | Реальные фото без согласия | Тестовые аккаунты и данные, правила [security.md](security.md) §3 | Dev4 |

## Открытые решения

Решения закрываются до зависимой реализации, а не все в конце проекта:

- тему, запреты, критерии разметки и качества — предложены в S1-10 ([policy.md](policy.md), [dataset.md](dataset.md)), подтверждаются в S1-14; веса-кандидаты — S1-09, пороги — S3-02;
- сроки хранения и правило отзыва согласия ([security.md](security.md) §3);
- нужно ли формально учитывать 152-ФЗ, или для учебного демо достаточно минимизации — уточнить у наставника;
- ~~поддержку WEBP и остальных форматов~~ — решено в S1-10: JPEG/PNG/WEBP по сигнатуре, выход JPEG ([policy.md](policy.md) §2);
- источник рейтинга и допустимость собственных голосов — единственный пункт, где допустимость эмулятора не следует из постановки;
- правила участия нескольких фото одного автора и ничьих;
- политику повторной отправки того же файла, если умолчание из [data-model.md](data-model.md) §4 не подходит;
- гарантированный TTL ссылок: в S1-04 фото/файл скачаны без токена, одна ссылка доступна спустя 3 ч 47 мин 7 с; это не гарантия срока жизни;
- ресурсы стенда — до экспериментов S1-09; уточнение нагрузки и условий эксплуатации — S5-05/S6-01;
- процедуру ручного разбора `publication_unknown` — с первой публикацией S2-11; расширенную сверку — S4-02;
- критерии приёмки реального MAX и условия выпуска — S5-01/S5-05.

S1-04 снял вопросы о полях callback и повторном удалении для тестового сценария:
см. [результаты](results/max-check.md). Эти наблюдения не задают гарантий
для всех прав, каналов и версий API.
