# S1-04: возможности MAX и контракты для эмулятора

Статус: проверка выполнена, результаты готовы к ревью. Дата: 24 октября 2026.
Владелец: Dev1. Проверки выполнены через `maxapi 1.2.3`; дальнейшая интеграция
Backend с MAX также использует `maxapi`.

Результат задачи — наблюдаемые возможности API, необходимые права,
ограничения и обезличенные примеры ответов. Конечный продукт реализуется
отдельно в задачах Backend и эмулятора.

## Права и возможности

| Возможность | Условия и права | Проверенный результат |
| --- | --- | --- |
| Сведения о боте | Валидный токен | `GET /me`: HTTP 200, `is_bot=true` |
| Polling | Один poller на токен, без активной webhook-подписки | `GET /updates` возвращает `updates` и следующий `marker`; получены текст, фото, файл, пересылка и callback |
| События канала | Бот — администратор | Получено `message_created`; `message.sender` может отсутствовать |
| Скачивание фото и файла | URL из вложения | HTTP 200 без `Authorization` и cookies; в проверенных случаях токен не нужен |
| Загрузка фото | Токен бота | `POST /uploads?type=image` возвращает `url`; multipart POST на upload-сервер — `photos` с токеном |
| Отправка сообщения в диалог | Доступ бота к диалогу | `POST /messages` с текстом и изображением: HTTP 200, возвращено созданное сообщение |
| Публикация в канале | Проверено при `is_admin=true` и `write` | Фото и `inline_keyboard` опубликованы одним `POST /messages` |
| Список сообщений канала | Проверено при `is_admin=true` и `read_all_messages` | `GET /messages?chat_id=…` возвращает посты |
| Чтение по ID | Доступ к сообщению | `GET /messages?message_ids=…` возвращает созданный пост |
| Кнопка и callback | Доступ пользователя к посту с кнопкой | Получен `message_callback` с пользователем, payload и исходным постом; `POST /answers` вернул `success=true` |
| Удаление | Проверено при `is_admin=true` и `delete` | `DELETE /messages?message_id=…`: HTTP 200, `success=true`; GET по удалённому ID — `messages: []` |
| Повторное удаление | Те же права и тот же ID | Снова HTTP 200, `success=true` |
| Нативные реакции | Пользователь поставил, заменил и снял реакцию | В polling без фильтра `types` отдельного события реакции не получено; в GET сообщения только `stat.views`, без реакций |

Отсутствие реакции в этих ответах не доказывает отсутствие другого API реакций.
Для собственного голосования подтверждены callback-кнопки; источник рейтинга
согласуется с наставником. Права без администратора и ошибки при отсутствии
отдельных разрешений не проверялись. Наблюдения не задают гарантий для всех
комбинаций прав и версий API.

## Вложения и обработка файлов

| Способ передачи | Тип вложения | MIME скачанного тела | Формат по сигнатуре |
| --- | --- | --- | --- |
| Фото | `image` | `image/webp` | WEBP |
| PNG как файл | `file` | `application/octet-stream` | PNG |
| PNG, загруженный через API и опубликованный как фото | `image` | `image/jpeg` | JPEG |

MAX может преобразовывать изображения; нельзя считать полученное фото
исходным файлом. Media должен проверять содержимое, а не только MIME
или расширение. Поддержку WEBP либо явное отклонение согласуют Dev2 и Dev4:
текущий план media рассчитан на JPEG/PNG.

URL фото и файла доступны без токена в проверенных случаях. Одно фото дважды
скачано по одной ссылке с совпадающим SHA-256; последняя проверка — спустя
3 ч 47 мин 7 с после записи ссылки. Это наблюдаемый возраст доступной ссылки,
а не гарантированный TTL. Время истечения неизвестно. Ссылки не должны
попадать в Git или публичные логи; недоступность нужно обрабатывать явно.

Входящее фото содержит `payload.photo_id`, `token`, `url`. Файл содержит
`filename`, `size`, `payload.url`, `token`, `fileId`. Для публикации проверена
синтетическая PNG-картинка, созданная программно без внешних ресурсов и людей;
личные фотографии и бинарные файлы в репозиторий не включены.

## Поля событий для адаптера и эмулятора

| Значение | Путь в событии |
| --- | --- |
| Тип события | `update_type` |
| ID входящего сообщения | `message.body.mid` |
| ID чата/канала | `message.recipient.chat_id` |
| Текст | `message.body.text` |
| Вложения | `message.body.attachments` |
| ID callback | `callback.callback_id` |
| Пользователь callback | `callback.user.user_id` |
| Payload кнопки | `callback.payload` |
| Пост callback | `message.body.mid` |
| Источник пересылки | `message.link.chat_id`, `message.link.message` |

Для inbox входящего сообщения кандидат ключа — источник, бот, `update_type`,
`message.recipient.chat_id`, `message.body.mid`; для callback — источник,
бот и `callback.callback_id`. Timestamp не является универсальным ID события,
а `seq` не считаем глобальным идентификатором.

`sender` необязателен. Пересылка требует отдельного разбора `link`.
В наблюдаемом callback исходный пост присутствовал; в других обстоятельствах
он может отсутствовать. Итоговые схемы адаптера согласует Dev2.

## Применение в спринтах

- **S1-05:** эмулятор отдаёт текст и фото через `GET /updates`, принимает
  `POST /messages`, сохраняет сформированные Backend ответы. Для работы того же
  SDK воспроизводятся также необходимые ему служебные методы, включая `/me`.
- **S2-12:** скачивание вложений, загрузка через `/uploads`, публикация
  и просмотр постов канала.
- **S5-02:** контрактные тесты сравнивают ответы эмулятора с записанными
  примерами MAX; совместимость адаптера и эмулятора проверяется через `maxapi`.

В [packages/contracts/max/fixtures/](../../packages/contracts/max/fixtures/)
сохранены 22 обезличенных примера ответов. Это данные для разработки
и будущих контрактных тестов. Вспомогательные боты и диагностические программы
в результат S1-04 не входят.

Критерии S1-04 по протоколу, примерам ответов, `contracts.md` §4 и `risks.md`
выполнены локально; изменения готовы к PR и ревью. Открыты решения об источнике
рейтинга, поддержке WEBP и гарантированном TTL. Эти вопросы не заменяются
предположениями о возможностях API.
