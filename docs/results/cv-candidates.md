# S1-09: кандидаты CV-моделей на CPU

Задача S1-09, Dev3. Замер 16 ноября 2026 скриптом [`apps/cv-worker/research/bench_cpu.py`](../../apps/cv-worker/research/bench_cpu.py) на первом срезе набора «Природа» (S1-15, 77 изображений, все `tuning`).

**Решение:** для темы — **OpenCLIP ViT-B/32 LAION-2B** (`clip-vit-b32-laion2b`), для NSFW — **Falconsai ViT** (`nsfw-falconsai-vit`). Обе модели укладываются по скорости даже в слабый ноутбучный CPU: около 0,4 с на изображение вместе. По памяти пара на границе критерия `policy.md` §7 (≤ 2 ГиБ) — см. «Ограничения».

## Стенд замера

| Параметр | Значение |
| --- | --- |
| CPU | Intel Core i3-1215U (2 P + 4 E ядра, 8 потоков, 15 Вт), без GPU |
| RAM | 16 ГБ |
| ОС | Windows 11, питание от сети |
| Python / PyTorch | 3.13, PyTorch CPU, потоков PyTorch: 6 |
| Входные изображения | 77 фото S1-15, приведены к виду после media worker: поворот по EXIF, ≤ 2048 px, JPEG q85 |
| Время на изображение | Декодирование очищенного JPEG + препроцессинг + инференс, по одному изображению, после 2 прогревочных |
| Память | Пиковая RSS процесса (`peak_wset`), каждая модель в отдельном процессе |

Ноутбук намеренно слабее сервера: если модель укладывается здесь, на стенде запас будет больше.

AUC — вероятность, что случайное `suitable` получит score темы выше случайного `off_topic` (1,0 — идеально, 0,5 — случайно). Это проверка здравого смысла на данных настройки, а не оценка качества: её делает S3-02 на контрольном наборе.

**Тема.** Обе CLIP-модели заметно лучше baseline «доля зелёного» (0,72), значит модели различают смысл кадра, а не цвет. На английских шаблонах `nature-v0` ViT-B/32 LAION-2B точнее и строже:

| При пороге 0,5 | ViT-B/32 LAION-2B | XLM-R ViT-B/32 |
| --- | --- | --- |
| `off_topic` со score ≥ 0,5 | 6 из 43 | 18 из 43 |
| `off_topic` со score ≥ 0,9 | 3 из 43 | 12 из 43 |
| `suitable` со score < 0,5 | 1 из 21 | 0 из 21 |

Мультиязычная модель в 2,4 раза тяжелее по весам, требует 3,6 ГБ на пике и чаще считает природой города и постройки (замок, Амстердам). Её единственное преимущество — русские шаблоны — не нужно: политика допускает `prompt_language: "en"`, а тему на русском видит только человек.

**NSFW.** На всех 77 безопасных изображениях Falconsai дал score ≤ 0,0004, AdamCodd — до 0,094. Falconsai вчетверо быстрее (вход 224 px против 384 px у AdamCodd). Полнота на настоящем NSFW-контенте **не проверена**: в наборе нет таких примеров.

## Разметка, на которую указала модель

ViT-B/32 уверенно не согласна с частью меток. По названиям и просмотру фото метки стоит перепроверить в S1-15, а не считать это ошибками модели:

| id | Метка | Score | Что на фото |
| --- | --- | --- | --- |
| nat-0020, nat-0021 | `off_topic` | 0,999 | Растение (эониум) крупным планом — по `dataset.md` §2 это `suitable`, если не горшок в помещении |
| nat-0031 | `off_topic` | 0,94 | Река в Хюэ, та же серия, что nat-0032 (переведена в `borderline`) |
| nat-0058 | `off_topic` | 0,77 | Подвесной мост в тропическом лесу |
| nat-0073 | `off_topic` | 0,59 | Пляж |
| nat-0022 | `suitable` | 0,33 | Баобабы — единственный заметный промах модели среди `suitable` |

## Ограничения и следующие шаги

- **Память на границе критерия.** Пара моделей требует ≈ 2,1–2,4 ГБ против ≤ 2 ГиБ в `policy.md` §7. Предложение: CV worker — один процесс с обеими моделями, лимит контейнера 3 ГиБ; критерий уточнить до ≤ 2,5 ГиБ после замера общего процесса в S3-01. Пиковое значение достигается при загрузке весов, рабочее — ≈ 1,0 ГБ (CLIP) и 0,7 ГБ (NSFW).
- **NSFW не проверен на положительных примерах.** Нужен прокси-набор `prohibited:nsfw` (`dataset.md` §4) к S2-09/S3-02; до этого пороги NSFW не выбираются.
- **Данные малы и только `tuning`:** 21 `suitable`, 43 `off_topic`, 13 `borderline`. AUC здесь — ориентир, а не качество. Пороги и метрики — S3-02 на контрольном наборе.
- **Запрещённые категории шаблонами CLIP** (`violence`, `personal_data`, `spam`, `minors`) в этом замере не оценивались: нет размеченных примеров.
- Веса скачиваются с Hugging Face при сборке образа; в рантайме CV worker без интернета (`security.md`), ревизии закреплены таблицей выше.
- Воспроизведение: `uv run apps/cv-worker/research/bench_cpu.py --manifest <manifest.jsonl>`; результаты пишутся в `data/results/cv-bench/` (вне Git).
