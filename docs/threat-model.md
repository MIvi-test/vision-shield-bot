# Модель угроз первого сценария — предложение Dev2 для ревью Dev4

26 ноября 2026. Владелец модели — Dev4. Этот документ фиксирует проверяемую
реализацию S1-17/S1-18/S1-16 и известные границы, не является его AppSec-одобрением.

## Потоки и границы доверия

```text
Недоверенный браузер → Caddy → API → PostgreSQL
MAX-эмулятор → intake → PostgreSQL: inbox + заявка/аудит + outbox
PostgreSQL → dispatcher → RabbitMQ: UUID → notifier → MAX-эмулятор
```

Браузеру нельзя доверять роль, идентификаторы или содержимое запросов.
API проверяет сессию и роль при каждом чтении. Брокер не источник текста:
notifier получает только UUID и читает адресат/ответ из БД с проверкой источника.
БД, миграции и процессы Backend — доверенная серверная зона с credentials.
В локальном Compose БД/брокер не публикуются на host; HTTP только loopback.
Раздельные credentials/сети будущих workers — S2-01, не уже реализованная изоляция.

## Угрозы и меры

| Угроза | Реализованная мера | Доказательство / граница |
| --- | --- | --- |
| Чтение заявок без входа, роль organizer | Серверные проверки session/active/role, moderator/admin для списка/карточки | test_backend_panel.py, Compose/API acceptance |
| Подмена входа или logout с чужого сайта | Exact Origin/Referer + JSON для login, SameSite Strict, случайный CSRF для logout | Тесты отсутствующего/чужого Origin, CSRF и реальный браузер |
| Кража/повтор истёкшей сессии | HttpOnly cookie, токен в БД только SHA-256, 8 часов без продления, отзыв и ротация текущей сессии | Тесты срока, logout, повторного входа; HTTPS/Secure обязательны вне loopback HTTP |
| Подбор паролей / утечка БД | Salted scrypt N=16384,r=8,p=5; сравнение constant-time; 5 ошибок/мин по IP или имени | Тесты общего throttle и обновления development-хеша |
| Утечка MAX-ID, текстов или технических ошибок через панель | Явные проекции DTO, no-store, безопасные code/message | Тесты списка/карточки/500; фото и тексты inbox не выдаются |
| Дубли события/уведомления после сбоя | Уникальный inbox/outbox, marker в транзакции, confirm, sending до внешнего запроса, ACK после результата | SQL/SDK/Compose тесты; exactly-once внешнего эффекта не обещается |
| Подмена AMQP body / бесконечный повтор мусора | Только ограниченный JSON с UUID, source/bot проверяются в БД, reject без requeue | parse_notification/изоляция в test_backend_delivery.py; ручная диагностика, без DLQ replay |
| Проблемное входящее событие блокирует порцию | Полный rollback не теряет историю; требуется оператор | Известный DoS-риск, контролируемое восстановление — S4-01 |
| Перегрузка / заполнение очередей и БД | RAM/CPU/PID контейнеров, limit списка 1–100, login throttle | Это частичная защита; общий входной/исходящий лимитер — S2-05, нагрузочные пределы ещё не измерены |

## Остаточные риски и условия применения

- За Caddy IP-лимит общий: forwarded-заголовки не считаются доверенными.
  Для публичного доступа нужно настроить trusted proxy и лимиты тела/частоты.
- Sending/unknown требуют сверки. Удаление тома брокера при сохранённом
  published_at не восстанавливается автоматически; нужен оператор.
- Автоматическая очистка текстов inbox, старых сессий и throttle — S4-03.
  Сейчас только синтетические данные и отдельные тестовые аккаунты.
- Файлы не скачиваются и не декодируются; SSRF/декодер/превью проверяются
  в S2-03/S2-04/S2-08, а не считаются защищёнными отсутствующими компонентами.
- Модераторы читают все кампании по принятому v0; пользовательской/tenant
  изоляции панели этот контракт не задаёт. Производственный multi-tenant требует нового контракта.
